# Use a MAIOS competence with your AI

[Italiano](USO.md) · [Resource catalogue](../README.md).

A competence contains operating knowledge. Add an actual intent, relevant sources and the means your environment can use.

## In a chat

Choose one of the 25 resources. Open its **START_CHAT_EN.txt**, then copy or attach the entire file. Add what you are doing, the result sought, existing work and the tools available. The starter contains the complete English method and can work without access to the rest of this repository.

For broader work, make SKILL.md and pertinent references available too. If the assistant can read files, provide the complete resource folder. Request an updated work guide containing purpose, sources, reasons, attained state, useful learning and continuation. Save that guide and bring it to a later chat when persistence is unavailable.

The Italian counterparts are SKILL_IT.md, README_IT.md, AVVIO_CHAT_IT.txt and ESEMPI_IT.md. Original competence names remain unchanged across languages.

## In an agentic environment

A host or harness provides the model, tools, access and execution mechanisms. Make the whole resource folder reachable, retaining relative links. Connect its entry through the host's supported mechanism and entrust a real task. Availability, discovery and exercise are distinct observations.

If a competence with the same name already exists, compare capabilities and decide how to continue them without overwriting valid work or creating divergent instructions. Consult the host's current official instructions for a concrete installation rather than assuming this folder installs itself.

## With an existing kernel

Connect the resource according to its contribution: an operating competence does work, a metacompetence may form or transform methods, KA is a semantic kernel and FDLA operates causal correction within the work. Read the selected guide before adding another instruction layer. All resources need not be loaded for every assignment.

Provide the project's current kernel or guide. Reuse existing knowledge and competence where it already performs the function. Keep continuity in locations the project can actually reach.

## Without a kernel

Begin directly from the included method and your context. A project document, file or persistent activity prompt can initially provide continuity. Use databases, repositories and integrations when their functions serve actual work, rather than making them prerequisites for every case.

## When recurrence is useful

Use the environment's actual controller to create or update an entrusted activity. Recover an existing job when it has the same mandate. Read back identity, saved instructions, cadence or event, timezone and destination. A configured job and an observed future execution remain different facts.

When no controller is available, the assistant can prepare the activity and perform feasible work during the present session. Recurrence becomes actual when a real mechanism activates it. Local and web environments can differ in file access and availability; follow their current contracts for the selected setup.

## Observe first use

Entrust concrete enough work to recognize a useful contribution. Observe whether pertinent sources informed action and whether knowledge needed for continuation survived. In a different later case, observe whether a correction and its reason change choices.

For feedback, describe situation and result while removing private data. A result, limitation or unchanged outcome can improve both operating method and explanation.
