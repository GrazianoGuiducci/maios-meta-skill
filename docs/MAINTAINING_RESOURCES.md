# Maintaining the MAIOS public resource collection

This document is for maintainers of this repository. Each transferable kit teaches work in the recipient’s own project.

When an upstream competence changes, reconcile the operating knowledge that the public resource transfers. Follow the actual dependencies: English and Italian method, guide, examples, complete starter, edition, catalogue and ZIP. A public-page-only correction need not change an unchanged operating method.

When an entry declares runtime_sources, keep those actual sources available in the complete starter as well as in the folder. A language-specific tool_guide can explain their use and boundaries. Regenerating prose must not silently remove a deterministic capability from the no-file-access adoption path. Tool inclusion makes its code available; it does not install an executor or establish authority over real services.

The MAIOS website and the assistant’s resource snapshot are separate consumers. Update the source each consumer actually receives when the selected publication changes that knowledge. A source commit, a site publication and a backend activation have distinct effects and verification.

Development chronology and local test results remain in attributed development records or Git history. Convert their useful causal lesson into instructions the recipient can use. Organizational names should not stand in for functions missing in a receiving environment.

When one authored source serves a page and an operating kit, preserve their different depths. A page’s method cards can orient the reader while `operating_method` carries the developed body; the renderer must not replace it with those cards. Keep practical knowledge and complete worked cases in the starter. Derive an example count from the actual cases rather than prescribing three. Preserve attributed edition metadata when a resource has no separate native source title.

Present the capability through the work it enables across systems. Host-specific installation or discovery belongs in an identified adoption example. A button naming one host can narrow an otherwise portable resource; use a general adoption entry that reaches the actual instructions. Keep independent use, composition with existing capabilities and optional MAIOS Project Kernel integration distinct, preserving local learning and partial contributions when updating.
