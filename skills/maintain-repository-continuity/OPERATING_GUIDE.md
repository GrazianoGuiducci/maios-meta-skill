# Maintain Repository Continuity

## Reconcile the selected work with its shared source

Identify the owning checkout, current branch, selected paths, local changes, upstream and actual remote identity. A workspace container may contain several independent repositories. Do not attribute every dirty file to the current task. Preserve concurrent lanes and existing staged work; stage only the selected contribution. A tracking reference is a cached observation until refreshed through the authorized credential mechanism.

If remote and local work changed independently, inspect relevant overlap and preserve both valid contributions. Use the smallest integration that continues the selected work; a reset or forced synchronization can erase unrelated knowledge. Before sharing, review the selected diff and checks pertinent to the change. Commit and push through the repository's existing authority and credential policy, without printing or persisting secrets.

Verify what the actual remote contains and distinguish source sharing from installation, deployment or public runtime behavior. A source push can trigger a separate deploy in some projects; understand that project relation before invoking it. Preserve the exact shared identity and remaining recovery condition where later work needs them. A clean checkout does not establish product correctness, and an ahead/behind count alone does not select which branch's meaning should prevail.
