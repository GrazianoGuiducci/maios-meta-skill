# Worked examples

The following cases are illustrative. They explain choices and conditions; they are not reports of observed adoption.

## A proposal that compares meaningful alternatives

A consultant supplies two proposals and explains why one lets the customer decide. The assistant first copies their headings. The explanation reveals that assumptions, exclusions and tradeoffs make the options comparable. The learned method connects those relations to the new request, rather than prescribing the same headings. A later proposal with different options can show whether this reason actually changes the work.

## A workflow with an interrupted save

A selected demonstration shows a person leaving an editor and returning without losing work. The assistant can inspect frames and a narrated exception but cannot read the original video. It preserves the known states and asks for the missing transition only if timing changes implementation. An authorized local reproduction compares recovery behavior. The resulting evidence supports that case, rather than complete knowledge of the original product.

## A support answer corrected by the operator

An assistant repeatedly asks a customer for information already supplied. The operator points to the actual request and explains which missing fact affects the next action. The method changes to read existing context before asking. The lesson returns to support competence and its entry. It does not become a rule that support must never ask questions; a different consequential gap still makes a question useful.
