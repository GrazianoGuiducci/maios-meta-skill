# Comprendere e organizzare Editoriali

**Organize an AI editorial system that learns from its work**

[Italiano](README_IT.md) · Public edition 0.3.0 · English operating method

## What it does

Organizes editorial knowledge, its connections to domain expertise and the continuity of individual works, allowing experience to change the system.

## When to use it

When a team produces several forms of content but repeatedly has to reconstruct its methods, sources and corrections.

An editorial team can have many instructions and still need to explain its work again in every chat. This resource connects shared methods, domain knowledge and the knowledge specific to each work.
Start with an actual editorial task: the sources it needs, the decisions it must retain and the place where a correction should change later writing.

## First use

1. Copy or attach [START_CHAT_EN.txt](START_CHAT_EN.txt). It includes the English method, operating knowledge, worked examples and any supplied executable sources.
2. Add your actual project, intent, relevant sources, existing work and available tools.
3. Entrust the useful contribution and identify actions the assistant may perform. Preserve its guide for later reentry.

You can begin with: “Use this competence for this work: […]. These are the sources and available means: […]. Carry out the entrusted work and retain what will let it continue. Involve me where […].” Adapt this to knowledge already present; it is not a compulsory questionnaire.

## Method

### Reach the knowledge that shapes the text

Distinguish the author’s intent, domain facts, editorial methods and the reasons behind the work. Connect the useful locations already present.

### Correct the source of the choice

A missing method needs knowledge; an existing method that goes unread needs a better entry. Follow that difference.

### Maintain both the work and the shared method

The work guide preserves its thesis and dependencies. Knowledge useful elsewhere returns to the shared competence.

## Meta and autological relations

Writing a guide is editorial work. Forming the system that makes sources, methods and work memory available is a meta relation: the object becomes the ability to write and continue.

The relation becomes autological when the organizing method itself enters the work. If separating everything by channel hides a shared source, the competence can reform that arrangement as it works.

Autopoietic return means that experience changes the form through which later work becomes possible. It is different from autonomous publication or higher output; the changed method must participate in later use.

## Use in your environment

### In a chat

Paste or attach START_CHAT_EN.txt and add your context. It includes the complete English method. If the chat cannot retain files, request an updated work guide and bring it to the next conversation.

### In an agentic environment

Make this folder readable and connect its entry to relevant work through the host’s supported mechanism. Identify sources, tools and durable knowledge storage. Reading the package does not install services or account access.

### With an existing kernel

Integrate the capability into the guides and competences already in use. Compare the functions they preserve and change only the differences that affect the work.

### Without a kernel

Use the included operating method directly. Start from a real case and retain what lets it continue. Compose other resources when their knowledge becomes useful.

## Learning and continuation

A correction can change a single work, a shared editorial method or the way the system is organized. Preserve it where the next relevant choice will be made.
This edition provides a method and illustrative cases. Continuity in a recipient environment must be observed through later work.
