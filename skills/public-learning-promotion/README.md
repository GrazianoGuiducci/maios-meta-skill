# Public Learning Promotion

**Turn internal project learning into shareable knowledge**

[Italiano](README_IT.md) · Public edition 0.3.1 · English operating method

## What it does

Separates reusable learning from private details and chooses a public form faithful to what was observed or built.

## When to use it

When project experience could become a guide, method, resource or public case.

A project produces knowledge while solving problems, recognizing limits and changing its method. Some of that knowledge can help people who know nothing about the original project.
This competence identifies the shareable relation and preserves the conditions that make it meaningful. Its public form may be an observation, a guide, a usable capability or a research question.

## First use

1. Copy or attach [START_CHAT_EN.txt](START_CHAT_EN.txt). It includes the English method, operating knowledge, worked examples and any supplied executable sources.
2. Add your actual project, intent, relevant sources, existing work and available tools.
3. Entrust the useful contribution and identify actions the assistant may perform. Preserve its guide for later reentry.

You can begin with: “Use this competence for this work: […]. These are the sources and available means: […]. Carry out the entrusted work and retain what will let it continue. Involve me where […].” Adapt this to knowledge already present; it is not a compulsory questionnaire.

## Method

### Identify reusable learning

Start from a specific event or understanding: what happened, what was learned and which later choice could change. Identify value for an external recipient, such as understanding, use, inspection, collaboration or research. A code change or a new label is not by itself a reason to publish. An open question can still be useful when its status is clear.

### Generalize while keeping the conditions

Separate the useful mechanism from person-, client- and environment-specific details. Determine what survives in another case and which conditions must travel with it. Removing names is insufficient: a configuration-dependent problem does not become universal. A neutral example can explain the mechanism if it is identified as illustrative.

### Preserve knowledge status

Distinguish observation, interpretation, implementation, exercise, repetition and external validation. A successful internal case is not a general performance result. Conversely, describe an established capability at the level its evidence supports. Keep decision-relevant uncertainty and scope visible in the main explanation.

### Choose the form and recipient

Let the relation determine the form: a clarified failure can become a practical note, a repeatable method a guide, a capability a kit and an unresolved relation a research question. Use an existing public derivative when appropriate. Product truth and editorial expression remain distinct responsibilities; one event can inform several recipients.

### Transfer usable capability

When forming an operating resource, include the knowledge needed to perform and continue the work: accessible sources, decisions, conditions, tools and learning. A well-described principle is not the same as a received capability. Replace private dependencies with usable entries. A simple article does not need an unnecessary installation or package.

### Learn from sharing

Protect personal data, credentials, private relationships and undisclosed strategy before a public effect. Preparation does not send or publish. After authorized sharing, use misunderstandings, critique and use cases to identify what should change: product, writing, distribution or the generalization method itself.

## Meta and autological relations

The work has a meta relation when it takes another activity's learning as its object and forms a transferable capability. Not every observation requires a new product.

An autological relation appears when public consequences change how learning is recognized and generalized. A guide that omitted a decisive condition teaches this competence what to preserve next time. That learning is distinct from automated publishing.

## Use in your environment

### In chat

Attach or paste START_CHAT_EN.txt, which contains the complete method, and add your context. The AI can work in the conversation's language. Retain the result and useful guidance if you want to resume in another chat.

### In an agent environment

Make the competence folder readable and have the agent read SKILL.md for the relevant work. Connect real sources and tools according to the environment's instructions. The kit does not install accounts, memory or recurring execution.

### With or without a kernel

With an existing kernel, connect the method to the competence or guide already responsible for the work. Without one, apply the instructions directly and preserve useful knowledge in the project or a reusable note.

## Application examples

## Learning and continuation

Keep the event, initial interpretation and later understanding attributable. Public feedback can improve the resource without rewriting what the original case actually showed.
