# Govern Source to Runtime — practical operating knowledge

## Credentials remain with the node owning their policy

Use your environment’s authorized adapter, with noninteractive authentication where required. Never print, embed in source or relay a local token to another host, including encoded forms. An immutable artifact or bundle can carry a revision without its credential when that transfer is entrusted. Access failure does not authorize another account.


## Effective configuration can differ from the neighboring file

A server may include an independent copy rather than the expected template. Read the configuration actually consumed, file type and bytes. A canonical path alone does not establish a symlink. Preserve module and dependency resolution in isolated checks: a wrong test prefix can falsely attribute a failure to the candidate.


## Health has its own timing and forms

After restart, await convergence within a short deadline and retain the last observation. Connection refusal during startup is not definitive failure. A successful oneshot may return to inactive: retain its result, exit code and terminal check rather than claiming continuous activity. A manual check preserves the actual user and group.


## A new identity does not erase every earlier proof

Reuse evidence only for an applicable relation with its original identity. Refresh revisions, concurrency, artifact, controller and destination where they could change the effect. A changed method or controller reopens pertinent dependencies; a local contradiction need not restart everything. Configured instructions do not replace the last installation actually confirmed.


## Declared support and executed proof are different facts

Technical minimum, declared platforms and exercised matrix are distinct. Check dependency attribution against its owner’s tag and commit, including annotated tags. A rebuilt archive changes identity: reread the current result before immutable release. A small file diff alone does not determine the compatibility meaning of a change.


## Recovery follows all changed effects

Returning to a commit need not restore data, notifications or external services. Qualify restoration or compensation with their owners. Keep the previous version independent; forced shared-history rewriting is no substitute for recovery. Final cleanup concerns only identified, verified files belonging to that attempt.


## Included tools read data rather than certify the world

scripts/reduce_release_state.py reduces supplied observations to a next action; scripts/validate_effect_request.py checks coherence, identities, services, recovery and effect selection against included schemas. Read TOOLS.md for examples and commands. A ready result is relative to supplied evidence: neither tool contacts accounts, publishes, restarts or grants permission.


## Automation belongs to a qualified transition

One successful procedure does not govern every server automatically. Automation needs a narrow contract, idempotency, privilege separation, terminal observation and recovery exercised in the relevant environment. Branches, diffs, logs and publication artifacts can expose information too: transfer reusable knowledge while retaining private topology and credentials.

## Publication learns from its actual path

The method and deterministic validators are available; the kit does not provide universal automatic deployment. Each environment owns its executors, access and policy.

An observed result can teach a reusable relation. A later non-identical use shows where that learning continues and where the method needs refinement.
