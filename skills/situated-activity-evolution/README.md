# Situated Activity Evolution

**Improve a recurring AI activity through its results**

[Italiano](README_IT.md) · Public edition 0.3.1 · English operating method

## What it does

Understands why an activity creates useful knowledge, repeats unused output or encounters new possibilities, then forms an appropriate continuation.

## When to use it

When an automation keeps running but its context, sources or intended recipient have changed.

An activity can execute its prompt correctly while becoming less useful. The problem may lie in its sources, method, recipient or connection to the project.
This competence takes the activity itself as its object: it understands the differences it produces and how continuation could improve. It complements Meta-Activity when an existing recurring activity needs reconsideration.

## First use

1. Copy or attach [START_CHAT_EN.txt](START_CHAT_EN.txt). It includes the English method, operating knowledge, worked examples and any supplied executable sources.
2. Add your actual project, intent, relevant sources, existing work and available tools.
3. Entrust the useful contribution and identify actions the assistant may perform. Preserve its guide for later reentry.

You can begin with: “Use this competence for this work: […]. These are the sources and available means: […]. Carry out the entrusted work and retain what will let it continue. Involve me where […].” Adapt this to knowledge already present; it is not a compulsory questionnaire.

## Method

### Start from a real difference

Read the activity's purpose, current configuration, sources, means and recipient. Use a real result or project change: repeated output, lost access, missed possibilities, successful contributions or overlap. A fired schedule does not prove completed work, and silence does not prove uselessness. Reconsider the activity when a material relation changes.

### Understand who can use the result

Follow the path from source to result and use. Distinguish information seen, prepared, stored, received and exercised. A report in a folder does not prove that its recipient read it. Value can mean a better question, a prepared decision, an avoided error or a retained possibility. Unknown use is not zero value.

### Change the responsible relation

If knowledge is missing, deepen the relevant method. If it exists but is not used, repair the entry or recipient connection. Compare purpose, sources and consequences before combining overlapping activities. A better source, cadence or stopping condition may suffice. Preserve the original purpose and valid decisions.

### Prepare what makes later work useful

When repeated reports appear saturated, the limit may belong to the repeated question. Look for a capability, relation, tool or condition that would change what the next run can do. Preparing a recipient to use a result can matter as much as finding another source. Develop a situated possibility without multiplying tasks merely to show improvement.

### Apply and observe the relevant change

Correct the method within authorized work. Changing a schedule, pausing or deleting an activity requires the actual mandate and controller. Preserve concurrent changes and read back saved effects. New instructions represent a change; later runs and their consequences show whether it participates. Do not retire useful work merely because it produces no notifications.

### Continue the learning

Return the smallest meaningful difference to the recipient, preserving source, meaning and reentry conditions where needed. Retain why the activity's method changed. If experience corrects how usefulness, saturation or overlap is understood, update this competence. A deferred possibility can remain available without creating another job.

## Meta and autological relations

The meta relation concerns the activity as a continuing capability: how it searches, produces and serves a recipient. A time-based trigger is only one of its means.

An autological return can change how this competence recognizes usefulness. An unread report may expose a missing connection rather than useless research. Autonomy instead concerns executing actions with actual means and authorization; it is not the same as this understanding.

## Use in your environment

### In chat

Attach or paste START_CHAT_EN.txt, which contains the complete method, and add your context. The AI can work in the conversation's language. Retain the result and useful guidance if you want to resume in another chat.

### In an agent environment

Make the competence folder readable and have the agent read SKILL.md for the relevant work. Connect real sources and tools according to the environment's instructions. The kit does not install accounts, memory or recurring execution.

### With or without a kernel

With an existing kernel, connect the method to the competence or guide already responsible for the work. Without one, apply the instructions directly and preserve useful knowledge in the project or a reusable note.

## Application examples

- Help a research radar stop rediscovering the same news.
- Connect research results to the competence that needs them.
- Understand whether overlapping activities should be combined.

[Read the examples](EXAMPLES.md). Cases illustrate possible use; they are not evidence of a recipient’s deployment.

## Learning and continuation

Retain a change when it helps the next use. This specialist competence can itself be simplified or absorbed by a better-suited capability: useful work matters more than preserving its current form.
