## Conduct the plugin field from the actual job

A plugin task may concern product purpose, component design, packaging, installation, discovery, authentication, controlled actions, evaluation, distribution, portability or troubleshooting. Let the work select the knowledge needed. Do not run every family as a checklist. ## Put each function in a component that can supply it

A skill carries method, examples and situated decisions. A service/tool layer can supply live data, authentication and controlled actions. UI makes human-visible state and intervention useful when the work benefits. Lifecycle actions require a host that actually executes the corresponding hooks; a file in an archive does not establish runtime execution. A specialist process is optional and requires the host's actual mechanism and the person's selected mandate. Provider-specific constructs belong to that incarnation rather than silently redefining the portable source.

Make a public operation self-contained: bundle or explicitly declare the components required for the intended user goal. A private combination of several installed connectors does not mean another recipient receives those means. Keep durable project knowledge outside an uninstallable package cache; distinguish installed files, disposable local state and the project's continuing record.

## Resolve discovery and execution separately

A technically valid package may be uninstalled, disabled, absent from the present session, undiscovered, unauthenticated or unused. Inspect the actual failing relation. The name and description must expose the recognizable goal so the method can be reached. Body knowledge cannot help if discovery never supplies it. A connected tool may still lack the data permission or exact effect mandate needed for the action.

Put enforceable access and data controls at the service boundary. Model instructions guide conduct but do not replace server checks. Distinguish authenticated identity, service authorization, host permissions and the person's mandate. Use least privilege and minimize private data exposed to tools, logs and UI. Inspect executable scripts, hooks, dependencies and untrusted inputs where their behavior changes trust or use. Keep credentials out of source and skill text.

## Use cases that distinguish causes

Choose a case capable of exposing the suspected loss: direct or indirect intent, incomplete input, unrelated request, follow-up, unavailable connection or missing permission. These are choices, not a compulsory quota. Observe activation, completeness, unsupported inference, tool use, preserved authority and context/process cost where material. Retain version, conditions, actual result and the responsible owner. Do not repair an authentication failure by changing semantics or a semantic failure by merely renaming the package.

A search result or indexed repository view may be stale. When freshness changes action, recover the exact current owner coordinate and read the smallest decisive source directly. Preserve previous observations with their own scope. For distribution, distinguish a local prototype, shared repository, team installation and public submission. A source push is not installation or public approval. Port user intent, method, source/effect distinctions and useful learning while translating manifests, tools, configuration, UI and runtime mechanisms through the receiving host.
