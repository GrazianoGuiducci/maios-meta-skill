# Incarnate Neutral Kernel Node

**Start an AI assistant with its own identity and continuity**

[Italiano](README_IT.md) · Public edition 0.2.0 · English operating method

## What it does

Helps a node begin from its own purpose and means, distinguishing the shared package from installation and the work that follows.

## When to use it

When transferring a kernel or a family of competences to another assistant, team or environment.

An assistant can receive a mature method and begin its own project, with its own identity, sources and learning.
This resource forms that passage: from shared capability to the recipient’s first useful work and later reentry in a new conversation.

## First use

1. Copy or attach [START_CHAT_EN.txt](START_CHAT_EN.txt). It includes the complete English operating method.
2. Add your actual project, intent, relevant sources, existing work and available tools.
3. Entrust the useful contribution and identify actions the assistant may perform. Preserve its guide for later reentry.

You can begin with: “Use this competence for this work: […]. These are the sources and available means: […]. Carry out the entrusted work and retain what will let it continue. Involve me where […].” Adapt this to knowledge already present; it is not a compulsory questionnaire.

## Method

### Understand the new recipient

Start with purpose, sources and actual means, retaining what must continue across sessions.

### Cross a first complete piece of work

Connect entry, competence, result and reentry guide in forms the recipient can actually use.

### Cultivate the node without overwriting it

Shared updates compose with local knowledge. Learning returned to others carries the method while leaving private identity and state with the node.

## Meta and autological relations

The meta relation forms the conditions through which a recipient can understand, act and evolve its competences.

The starting method can become its own object. If reentry loses the reasons behind choices, experience can change both the node’s guide and the way the next start is prepared. This is the autological relation.

Shared package, configuration, installation, conversation and learning have distinct states. Autopoietic continuation requires local learning to reach the form through which the node works again.

## Use in your environment

### In a chat

Paste or attach START_CHAT_EN.txt and add your context. It includes the complete English method. If the chat cannot retain files, request an updated work guide and bring it to the next conversation.

### In an agentic environment

Make this folder readable and connect its entry to relevant work through the host’s supported mechanism. Identify sources, tools and durable knowledge storage. Reading the package does not install services or account access.

### With an existing kernel

Integrate the capability into the guides and competences already in use. Compare the functions they preserve and change only the differences that affect the work.

### Without a kernel

Use the included operating method directly. Start from a real case and retain what lets it continue. Compose other resources when their knowledge becomes useful.

## Application examples

- Start an assistant for a new project.
- Transfer a method between chat and an agentic environment, adapting persistence.
- Return useful learning without copying another node’s private memory.

[Read the examples](EXAMPLES.md). Cases illustrate possible use; they are not evidence of a recipient’s deployment.

## Learning and continuation

The recipient first preserves learning in its own method. A transferable relation may later contribute to a shared source, with its provenance retained.
Use in a different situation makes continuity observable. A copied repository or a completed profile does not demonstrate it alone.
