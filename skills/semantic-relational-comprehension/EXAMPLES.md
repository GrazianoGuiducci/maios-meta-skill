# Worked examples

The following cases are illustrative. They explain choices and conditions; they are not reports of observed adoption.

## Two accurate records form an inaccurate present

A system report lists a feature from one release and an incident from an older configuration. Each record is authentic. The assistant preserves their dates and conditions before combining them. The comparison then concerns a historical transition, rather than a claim that both conditions currently coexist. A test of the current release would support a different, specifically current claim.

## A new label hides an existing ability

A team requests a new memory module. The assistant compares the required function with the project's existing guides, current-state entry and retrieval. It finds that the method exists but the entry does not reach it. Reconnecting that consumer can solve the actual loss. A genuinely absent persistence mechanism would require a different result; the word memory alone does not select either architecture.

## A recursive discussion loses its originating question

A research conversation keeps refining an internally coherent diagram. The person points out that the diagram no longer addresses the original relation. The assistant recovers the last source-bound question and combines it with what the discussion actually learned. It preserves useful distinctions, changes the diagram's role and continues from the present instead of treating its latest summary as an independent source.
